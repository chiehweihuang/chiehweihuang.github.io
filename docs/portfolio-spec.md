## 4. 成功條件與非目標

### 本版可驗收的成功條件

- 從首頁一個連結可到主要作品或 Decision Note，兩個連結內可到 Note 的證據。
- 每件精選作品清楚說明問題、作者貢獻、目前結果及限制；不要求圖片才能理解。
- 不認識和碩的讀者仍能從首頁辨識作者的工作經驗與作品。
- 中英文的姓名、作品歸屬、服務承諾、日期及證據限制一致。
- 聯絡入口可透過鍵盤操作，也提供可選取、複製的 email 地址。
- 通過第 11 節列出的內容、功能與視覺驗收。

讀者理解度需要實際回饋。首次內容試讀可請讀者回答「他做過什麼？哪一件作品支持你的理解？哪些能力還不能從本站推得？」並記錄誤解；未執行前不宣稱已驗證定位。瀏覽量或 email 點擊不等於理解度、信任或付費需求。

### 不在本版範圍

- 建立完整顧問產品線、定價方案、newsletter、CMS、登入或預約系統。
- 重新定義作者職稱，或宣布已成立的 Physical AI／無障礙 audit 事業。
- 製作沒有資料支持的 dashboard、成效圖、客戶 Logo 牆、證言與市場數據。
- 新增完整研究、重做部署地圖資料模型、修改 Beacon 或 Bright Raven 產品。
- 自動發布、merge、commit、push、外聯或建立新的追蹤服務。

- 維持靜態 HTML、共用 `style.css` 與 `site.js`；不新增套件或後端作為預設。

- 導覽具有目前頁面狀態、skip link 與可見焦點；窄螢幕換行排列，不用橫向捲動藏連結。

- JavaScript 關閉時，主要文字、頁面連結與 email 仍可用。地圖至少保留可讀資料與方法文字。
- 更新共用 CSS 時同步頁面的 cache query；檢查新載入與重新載入，不能將快取舊頁當成新版本驗收。
- 不改寫 `decision-notes/evidence/` 的歷史來源或結果。新的驗收證據使用獨立路徑，不直接執行會覆寫歷史 `result.json` 的腳本。
